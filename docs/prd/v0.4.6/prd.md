# WatermarkFlow v0.4.6 产品需求

## 背景

用户反馈：剪贴板里有复制好的图片时，点击菜单栏“选择模板快速生成并复制”中的任何模板，总是弹出主窗口且图片没有叠加水印，问题间歇出现。排查确认失败路径为快速生成的异常分支：微信等应用复制图片时会在剪贴板放置临时目录中的文件 URL，临时文件被清理后读取必然抛错；而失败原因只显示在主窗口右上角一行 11pt 状态小字中，用户无从得知，看起来像“随机坏掉”。

## 目标

- 临时文件被清理后，若剪贴板仍带有原生图片数据，快速生成应直接回落使用原生数据并成功输出水印图。
- 没有原生数据可回落时，必须以用户能看到的方式说明失败原因和补救动作。
- 系统“从其他 App 粘贴”权限被拒绝时，提示应指向系统设置，不再误报“没有图片”。
- 快速生成链路必须留下可事后排查的日志。
- 不改变多文件拒绝、HTML 单图回退、512 MB 上限和输出像素策略等既有行为。

## 验收标准

- 文件 URL 失效且带原生像素的剪贴板可直接生成水印图，像素尺寸不变。
- 仅失效文件 URL、无原生像素时，报错为“复制的图片文件已失效，请重新复制图片”。
- 快速生成失败时主窗口弹出说明性警告框，状态区同步显示“快速生成失败：…”前缀文案。
- 上一次快速生成处理中再次触发时状态区有提示，不静默忽略。
- 34 个核心测试、应用自检、Universal 构建与文档门禁全部通过。
