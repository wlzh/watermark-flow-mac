# WatermarkFlow v0.4.3 产品需求

## 背景

飞书等网页应用在部分复制操作中不会向系统剪贴板写入 PNG 或 TIFF，而只写入包含单个 `<img>` 的 HTML。此前快捷键只接受系统可直接解码的图片，因此会报“剪贴板中没有可读取的图片”、弹出主窗口，并保留上一次编辑图片，造成“快捷键失效”的误解。

## 目标

- 快捷键能够处理剪贴板直接提供的图片，也能处理只包含一张网页图片的 HTML。
- 网页图片回退仅发生在用户主动触发快捷键或手动载入时，后台监测不得自动联网。
- 下载与渲染不能阻塞主线程，连续按快捷键不能重复处理同一任务。
- 失败信息应区分没有图片、多张网页图片、不安全地址、下载失败和超大图片。
- 不改变模板、颜色、位置、快捷默认模板、快捷键或模板 schema。
- 菜单栏应允许直接切换快捷键默认模板，不要求打开主窗口，也不能在切换时立即处理剪贴板。

## 验收标准

- 原生 PNG/TIFF 继续直接处理，不经过网络。
- HTML 恰好包含一张 HTTPS 图片时，读取原图、套用快捷默认模板并把结果写回剪贴板。
- HTML 多图不擅自选择；HTTP、无法下载、无法解码及超过 64 MB 时给出明确提示。
- 网页图片处理期间再次按快捷键不会启动第二个任务。
- “从剪贴板载入”与快捷键使用相同的主动回退能力；后台自动发现仍只处理原生图片。
- 全量回归测试、本机安装和真实飞书复制场景通过，用户配置文件安装前后不变。
- 菜单栏“设置快捷默认模板”列出全部模板、勾选当前项，选择后持久化并用于下一次快捷键处理。
